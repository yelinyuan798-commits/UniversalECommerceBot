# 安装和使用说明

第一次打开，直接用默认客服试聊即可，不用先填商品，也不用 AI 密钥。它会使用系统自带的接待话术；需要确认商品细节、退款或投诉时，记入人工待办。

想让机器人报具体价格、介绍商品或按底价还价，再切换到 **“按商品定制”**。连店铺之前，先自己问几句，看看回复是否符合你的需要。

## 安装与启动

先安装 Python 3.11 或更新版本。Windows 安装 Python 时，勾选“Add Python to PATH”。

1. 打开 [GitHub 项目页面](https://github.com/yelinyuan798-commits/UniversalECommerceBot)，点击 **Code → Download ZIP**，下载后解压。下面的操作都在解压后的文件夹里做。
2. **第一次安装**：Windows 双击 `setup.bat`；macOS / Linux 在项目文件夹打开终端，运行 `bash setup.sh`。等它提示安装完成。
3. **以后每次打开**：Windows 双击 `start.bat`；macOS 双击 `start.command`，或运行 `bash start.command`；Linux 运行 `bash start.command`。
4. 浏览器没有自动打开时，手动访问 `http://127.0.0.1:8765`。

平时不用重新安装。macOS 如果提示没有执行权限，改用 `bash start.command` 启动即可。

<details>
<summary>用 Git 下载或手动安装</summary>

用 Git 下载后，运行安装和启动脚本：

```sh
git clone https://github.com/yelinyuan798-commits/UniversalECommerceBot.git
cd UniversalECommerceBot
bash setup.sh
bash start.command
```

macOS / Linux 手动安装：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python main.py console
```

Windows 将 `python3` 换为 `python`，将 `.venv/bin/python` 换为 `.venv\Scripts\python`。启动命令后加 `--port 8766` 可以更换工作台端口。

安装脚本会下载 Chromium。浏览器程序放在系统缓存里，登录资料和聊天记录放在项目的 `data/` 目录里。更新版本后如果依赖有变化，再运行一次安装脚本。

## 直接用默认客服

1. 首次使用时，工作台已经选中 **“直接用默认客服”**。不用填写左侧商品表单。
2. 在右侧点击 **“打招呼”**、**“问价格”**、**“问发货”**，看系统默认回复。输入“我要退款”可检查人工接管；之后点 **“重新开始一个会话”** 继续试聊。
3. 回复合适后，点击 **“去连接店铺”**，按下面的步骤登录和设置平台。

默认客服不会读取商品页面。没填资料时，询价、库存、发货问题只引导买家查看页面；要回答具体金额、参数或承诺日期，请改用商品定制。人工待办在本机工作台查看，不是平台原生的客服转接。

已有定制配置会继续使用原模式。想改用默认客服，先停止机器人，再点击 **“直接用默认客服”**；原来的商品资料会保留。以后点击 **“按商品定制”** 就能继续使用，切换后会开启新的本地试聊会话。

## 填商品和试聊

1. 打开 **“商品与规则”**，选择 **“按商品定制”**，填写店铺、商品名称、“商品所属平台”和“平台商品 ID”，再填价格、底价、库存、发货规则及常见问答。试用时可以填样例，连自己的店铺前要换成真实资料。
2. 不想讲价，就把“议价规则”选为 **“不议价，只报标价”**。价格、底价和转人工关键词都填在对应的框里，确认后点击 **“一键生成并保存配置”**。
3. 在右侧 **“先试着聊一聊”** 选择“咨询商品”，点击 **“问价格”**、**“试议价”**、**“问发货”**，也可以自己输入问题。这里的消息不会发给真实买家。
4. 输入“转人工”试试看。机器人暂停回复后，点 **“重新开始一个会话”**，就能继续试聊。

**添加下一件商品**：填写另一件商品的平台、ID 和资料，再点“一键生成并保存配置”。同一平台、同一 ID 会更新原来的商品；换一个平台或 ID 就会添加新商品。保存后，在右侧“咨询商品”中选择它。

需要一次修改多件商品，可以展开 **“多商品 / 精细编辑”**，改完点 **“保存完整配置”**。同一个商品 ID 在不同平台可以用不同价格；单独给某个平台填的资料，会优先于“所有平台共用”。**连店铺时，商品 ID 一定要和商家页面上的商品对应。**

“定制条件”可以写补充说明，也可以单独写一行“不议价”。其他自由文字主要帮助识别买家在问什么；报价、是否议价和转人工还是按对应字段执行。

不填 AI 密钥也能用商品规则和常见问答。想使用模型时，在自己电脑的 `config/.env` 里填写。商品资料保存在 `config/merchant.json`，平台设置保存在 `config/platforms.local.json`；这些文件不要上传到公开仓库。

## 连上自己的店铺

默认模式不要求商品配置，但仍要连接自己的店铺。准备好商家账号，再准备一个测试买家账号。打开 **“平台接入”**，在配置框里找到你要用的平台：

- 把 `enabled` 改为 `true`，表示启用；先保留 `dry_run: true`，表示只看消息、不发回复。
- 闲鱼登录资料填在自己电脑的 `config/.env` 里。
- 淘宝、京东等网页平台，需要填写客服消息页地址，以及页面上哪里是买家消息、商品和发送按钮。这一步要按实际页面设置。默认留空的“选择器”不能照抄测试页；不熟悉网页设置时，请让接入人员按[这份说明](#浏览器适配器配置)处理。

设置好以后，按这个顺序来：

| 第几步 | 怎么做 |
| --- | --- |
| 1. 保存 | 点 **“保存接入配置”**，确认要用的平台已启用，并保留 `dry_run: true`。 |
| 2. 先看回复 | 点 **“开始观察”**。网页平台在弹出的浏览器里登录，再让测试买家发一个问题。检查买家、商品和准备回复的内容是否正确；这时还不会发送。 |
| 3. 先停下来 | 点 **“停止”**。不能在运行中直接切换模式。 |
| 4. 打开发送开关 | 把这个平台的 `dry_run` 改为 `false`，再点 **“保存接入配置”**。其他平台可以继续保留 `true`。 |
| 5. 开始回复 | 点 **“开启自动回复”**，确认弹出的提示，并查看平台是否连上。 |
| 6. 买家再问一次 | 让测试买家发一条**新消息**，去买家端确认收到一次正确回复。接着按后面的[测试清单](#验收标准)检查。 |

观察时看过的消息不会补发，所以最后一步要发新消息。不要删去重记录来重试，以免重复回复顾客。

平时打开 **“消息与人工接管”**，就能看哪些消息已经回复、哪些需要你处理。你处理完后，点 **“恢复自动回复”**。想暂停所有平台，点顶部的 **“停止”**。

<details>
<summary>用命令行运行</summary>

在已激活的虚拟环境中执行，也可以换成对应的 `.venv` Python 路径：

```sh
python main.py doctor       # 检查依赖与配置，不检查店铺是否登录

```

检查配置通过以后，仍要用测试买家发消息试一遍。

</details>

## 官方能力核查

以下是 2026-11-02 核查的官方公开文档；具体账号当前可获得的权限以平台控制台为准。

- 淘宝存在官方机器人下发接口 [`taobao.message.chatrobot.async`](https://developer.alibaba.com/docs/api.htm?apiId=48631)。文档要求用户授权，并使用平台颁发的 `request_token`；请求头中的 `request_id`、`tenant_id`、`action_mode` 来自上行事件。因此只知道接口名称或持有普通网页 Cookie，不等于已经具备完整机器人收发权限。
- 淘宝的[智能客服咨询商品接口](https://developer.alibaba.com/docs/api.htm?apiId=54107)标注需要授权，并要求在聚石塔内调用。不要把公开商品页查询与商家客服商品上下文混为一谈。
- 京东官方列有[咚咚机器人 API 类目](https://jos.jd.com/apilist?apiGroupId=3834&apiGroupName=B2C-%E5%AE%A2%E6%9C%8D-%E6%9C%BA%E5%99%A8%E4%BA%BA-%E5%92%9A%E5%92%9A1.0)。公开目录不足以确认本店铺已取得某个接口权限。
- 京麦 [JSSDK 的 `sendDongdongMsg`](https://jmw.jd.com/docs/jssdk/jssdk-mobile/api.html)限定在由咚咚启动的插件页面内使用，目标是当前聊天用户，不能当作通用服务端消息发送 API。
- 京东[商家咚咚官方下载页](https://im.jd.com/seller/download/)提供 [Web 入口](https://dongdong.jd.com/)。是否能接待客户还取决于登录账号及客服权限。

本版本没有把未取得授权、未联调过的官方 API 包装成已可用接口。若店铺已有官方机器人资质，可以保留客服核心，另写接收上行事件、验签和调用授权下发接口的适配器。

## 浏览器适配器配置

在对应平台配置的 `config` 对象中填写浏览器参数，平台顶层保留 `dry_run: true`。下面展示字段格式；`[data-*]` 是本地测试页面的约定，**不是淘宝、京东或其他平台的通用网页选择器**，必须根据当前商家页面逐项替换。

```json
{
  "dry_run": true,
  "config": {
    "url": "https://dongdong.jd.com/",
    "profile_dir": "data/browser/jd-test-shop",
    "headless": false,
    "poll_interval": 2,
    "process_existing": false,
    "selectors": {
      "ready": "[data-workbench-ready]",
      "conversation": "[data-active-conversation]",
      "conversations": "[data-conversation-entry]",
      "messages": "[data-message-id]",
      "message_text": ".message-text",
      "composer": "textarea",
      "send": "button.send"
    },
    "attributes": {
      "conversation_id": "data-conversation-id",
      "user_id": "data-user-id",
      "item_id": "data-item-id",
      "message_id": "data-message-id",
      "direction": "data-direction",
      "delivery_status": "data-status",
      "message_timestamp": "data-timestamp"
    },
    "inbound_value": "inbound",
    "outbound_value": "outbound",
    "sent_values": ["sent", "delivered"]
  }
}
```

选择器使用标准 CSS 语法，不使用 Playwright 专用的 `text=` 或 `:has-text()`。字段需要满足以下条件：

- `ready` 只在已登录、可接待状态下出现。不能用登录页也存在的 `body` 之类元素代替。
- `conversation` 必须唯一指向当前会话面板，该面板必须携带可靠的会话和买家标识。商品标识对应商家配置中的产品。
- `messages`、`message_text`、`composer`、`send` 都在当前会话面板内查找，避免匹配到其他聊天窗口。
- 每条消息必须有稳定的 `message_id` 和明确的收发方向，只有等于 `inbound_value` 的消息可以触发回复。不能用行号、显示时间或聊天文本代替稳定消息 ID。
- `delivery_status` 指定发出的消息状态属性，只有等于 `sent_values` 中明确成功状态的回显才记为发送成功。仅出现消息气泡但无法确认状态时记为 `unknown`，需要人工核实，不自动重发。
- 可选的 `conversations` 用于切换会话列表；各行必须有对应的 `conversation_id`。未配置时只处理当前打开的会话。
- `message_timestamp` 必须对应每条消息的可靠创建时间，值可以是 Unix 秒 / 毫秒或带时区的 ISO 8601 时间。自动回复模式下，缺少有效时间的消息会被跳过并提示校准；明显来自未来的消息也会跳过。不要用页面渲染时刻代替消息创建时刻。
- `process_existing: false` 是默认值，跳过当前连接启动之前的消息；启动后新买家第一条带有效时间的咨询会正常处理。`true` 会允许处理历史消息，只能在明确需要补处理的测试场景使用。
- `profile_dir` 为专用目录，每个商家账号单独使用，不能多个浏览器进程并发打开同一目录。

若真实页面没有可稳定获取的会话 ID、买家 ID、消息 ID、创建时间、方向或发送状态属性，当前适配器不能直接启用；需要先针对该页面补充可靠的提取方式，或接入获授权的官方机器人接口。不要填假的标识来绕过检查。

## 真实店铺的准备

1. 在本机准备商家账号和一个独立的测试买家账号。不要使用正在服务的真实顾客来验证发送。
2. 在机器人专用浏览器目录登录工作台，完成平台正常登录与验证。登录状态只保留在本地，不放入 Git，也不发到聊天、工单或截图中。
3. 使用“按商品定制”时，商品 `id` 填实际平台商品标识，价格、库存、发货与售后规则填商家确认的数据。默认模式不需要商品资料，只做通用接待；没有填写的事实不能据商品名编造。
4. 先以预览模式观察读到的买家、会话、商品、消息方向与建议回复。预览通过后才启用实际发送。
5. 每个平台和店铺分别保留配置及验收记录。页面改版、账号切换或客服权限变化后重新验证。

## 验收标准

| 检查 | 操作 | 通过标准 |
| --- | --- | --- |
| 单条收发 | 测试买家咨询已配置商品 | 商家端识别正确，买家端收到一次正确回复 |
| 收件人隔离 | 两个买家同时咨询不同商品 | 回复分别送达对应会话，无跨会话商品信息 |
| 自身消息 | 商家手动发送消息 | 机器人不回复自己、不产生循环 |
| 历史消息 | 打开已有会话、刷新页面 | 历史记录不被当作新咨询批量回复 |
| 新买家首条 | 启动后让新的测试买家首次咨询 | 第一条咨询正常识别，不能误判为历史 |
| 观察切实发 | 观察一条消息，切换模式，再发新消息 | 旧观察消息不补发，新消息正常发送 |
| 重连与重启 | 同一消息重复推送，重启程序 | 不重复发送已处理回复；发送状态可追踪 |
| 发送失败 | 断网或让发送按钮不可用 | 不把失败或未知结果写成已送达，不盲目重发 |
| 会话切换 | 生成回复过程中切换聊天对象 | 不向新聊天对象发送旧回复 |
| 登录失效 | 退出工作台登录 | 停止发送并提示重新登录 |
| 页面变化 | 改动测试页面必要标识或选择器 | 停止自动发送，不能猜测收件人 |
| 价格规则 | 反复压价至低于商家底价 | 报价不低于设置底价 |
| 未知信息 | 咨询未配置规格或未知商品 | 询问或转人工，不编造规格、库存或承诺 |
| 人工接管 | 触发售后 / 投诉 / 人工关键字 | 记录待人工处理，会话暂停自动回答，人工恢复后再接待 |
| 长时间运行 | 对测试账号持续运行并断网恢复 | 留下运行时长和错误记录；短测不能宣称 7×24 稳定 |

记录每个真实测试的平台、日期、工作台版本/页面、测试场景、结果和必要的脱敏证据。凭据、买家个人信息和完整会话记录不应提交到公开仓库。

## 测试结果的含义

- 单元测试：验证商品规则、去重、状态与异常处理。
- 本地浏览器端到端测试：在项目自带的模拟商家页面验证读取、决策、输入、点击发送及防重复流程。
- 真实平台联调：验证当前线上页面 / 协议、账号权限、实际收发与登录失效。
