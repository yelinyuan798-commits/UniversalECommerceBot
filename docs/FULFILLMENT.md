# 订单与发货：先核实付款，再交付商品

工作台现在能处理三类商品。打开 **订单与发货**，按页面的三步设置即可。

| 你卖什么 | 填好什么 | 订单付款后怎么处理 |
| --- | --- | --- |
| 卡密、兑换码 | 商品对应规则，一行一条卡密 | 按购买数量分配，每个订单只分配一次 |
| 资料、下载链接 | 该商品的下载地址、提取码及说明 | 把保存的内容交给订单中的买家 |
| 实物 | 商品对应规则 | 进入待发货清单；寄出后填快递公司和单号，再回填订单 |

**实物目前不对接仓库，不自动购买面单，也不会替你把包裹寄出去。** 单号“已登记”只表示存进工作台；看到“已交付”才表示订单服务确认接收了这次回填。

## 第一次使用

### 1. 连接自己的订单系统

在“订单连接”里填写平台、店铺标识、接口地址和专用密钥，保存后点“测试连接”。密钥留空可以保留已有值，换接口地址需要重新填写。

聊天登录和订单授权是两件事。接通聊天不会自动获得付款状态或发货权限。这里需要的是你的商城，或你已授权的商家订单服务；不能填买家给你的网址。

**原独角商城已经提供配套接入代码**，安装方式见 [商城发货接口说明](https://github.com/yelinyuan798-commits/AI-daichong-neimu-dujiao-mod/blob/main/app/docs/merchant-fulfillment-bridge.md)。商城管理员部署后，把专用地址、店铺标识和密钥填进工作台。原商城自己的自动发卡商品继续由商城处理；工作台接管指定的人工履约商品，避免两边重复发货。

闲鱼、淘宝、京东、拼多多、抖店、快手小店、小红书千帆可分别保存订单连接、商品规则和发货记录。**这些平台目前通过下述统一接口对接已授权订单服务，还没有随项目提供七套开箱即用的官方订单与发货连接器，也没有完成真实店铺发货验证。** 仅有聊天 Cookie 不能开通自动发货。

测试连接只核对服务、店铺身份和支持的商品类型，不会发出商品。

### 2. 给商品设发货规则

填平台、店铺、平台商品编号；有不同规格时再填规格编号。选择卡密、资料或实物，并填写“每件最低实付”。

- **卡密**：保存规则后导入卡密，一行一条。重复导入的卡密会跳过；页面只显示数量，不回显正文。
- **资料**：保存地址、提取码和说明。正文留空会保留旧值；这里只发送你保存的文字，不替你托管文件或生成有期限的下载地址。
- **实物**：保存规则即可。订单经核验后会进入待发货清单。

最低实付使用平台结算给商品行的金额。运费单独核对，不当成商品款；币种必须一致。比如设为每件 10 元，买两件的商品实付至少应为 20 元。优惠后低于这个数会暂停，留给你核对。

### 3. 先试运行，再开始处理

先用订单号核验，或点“试运行”。它会读取已授权订单，检查商品、数量、付款状态和库存，**不扣库存、不发商品、不回填单号**。

确认无误后，启用订单连接。你可以点击正式处理单个订单，也可以勾选连接的“自动处理”，再点“开启自动发货”。工作台每 30 秒扫描一次待处理订单；程序需要保持运行。重新打开工作台时自动发货处于停止状态，需要你再次开启。

实物订单先在列表中登记快递公司和单号，然后点回填。回填前会再查一次订单，退款或关闭的订单不会继续处理。

## 看懂发货记录

| 状态 | 含义与下一步 |
| --- | --- |
| 待发货 | 实物还没回填单号，先完成寄件再登记 |
| 待交付 / 发送中 | 已分配内容，正在处理；不要另行换卡重发 |
| 已交付 | 订单服务返回了本次交付回执；不是买家已使用商品或已签收 |
| 已阻止 | 未付款、退款中、金额不符、缺规则、缺库存或明确交付失败；看原因修正后再核验 |
| 待核实 | 超时、掉线或程序中断，无法判断对方是否收到；先去订单系统核对，系统不会盲目重发 |

每个订单的每条商品明细只有一个发货任务。重复通知和重启扫描不会重复扣库存。已经分配的卡密会保留给原订单，即使失败也不会自动退回库存；明确失败后重试仍用原卡。修改资料内容只影响新任务，旧任务保留创建时的内容。停用规则会阻止尚未发送的任务。

发货不由 AI 决定。买家说“已付款”、聊天截图、AI 判断都不能触发交付。付款、买家、商品、数量和实付金额必须从商家授权订单系统重新查询，发送前再核验一次；服务端提交交付时还需在同一事务内复查订单状态。

## 本地数据放在哪里

- `config/fulfillment.local.json`：订单接口地址与密钥。
- `data/fulfillment.db`：商品规则、卡密、订单和交付记录。

这两处都被 Git 忽略；文件只给当前电脑用户读写。它们没有做数据库级加密，请保管好电脑账户和备份。卡密、资料正文和密钥不会进公开状态接口或 AI 对话。交付时，订单服务会收到该订单分配到的内容。

## 给订单系统开发者的接口约定

协议名：`uecb-fulfillment-v1`。接口基础地址固定由商家在本地保存，远程必须使用 HTTPS。工作台不跟随重定向，也不使用订单数据提供的回调网址。单次请求和响应上限 256 KB。

| 路径 | 返回内容 |
| --- | --- |
| `GET /health` | `ok:true`、`protocol`、`platform`、`shop_id`、`capabilities:["card","link","physical"]`；只列实际支持的类型 |
| `GET /orders?limit=50&cursor=...` | `orders:[{"order_id":"..."}]` 和 `next_cursor`，没有下一页时为 `null` |
| `GET /orders/{order_id}` | 从权威订单库实时读取的订单，结构见下方 |
| `POST /deliveries` | 完成交付后返回 `{"status":"sent","receipt":"稳定回执"}`；确定未交付返回 `{"status":"failed"}` |

所有接口返回直接 JSON 对象，不套 `data` 外壳。扫描列表只传订单号，工作台会另行查询和核验。分页需稳定，不能因上一页完成发货而跳过下一页；推荐以递增主键为游标。每轮完整扫描结束后从头开始，因此宕机期间的待处理订单也能被重新发现。一次最多处理 500 条，自动轮询会接着扫描后续页。

### 签名

服务端与工作台保存同一专用随机密钥，至少 32 字节。三个请求头：

```text
X-Fulfillment-Timestamp: Unix 秒
X-Fulfillment-Nonce: 随机唯一值
X-Fulfillment-Signature: HMAC-SHA256 十六进制小写
```

签名内容为以下五项用换行符连接，不带末尾换行：请求方法、包含查询参数的原始路径、时间戳、Nonce、原始请求体的 SHA256 十六进制。GET 请求体为空。服务端校验时间窗、恒时比对签名，拒绝短期重复 Nonce。

### 订单结构

```json
{
  "platform": "dujiao", "shop_id": "my-shop", "order_id": "order-123",
  "buyer_id": "stable-order-buyer-id", "status": "paid",
  "amount": "20.00", "currency": "CNY", "shipping_amount": "0.00",
  "items": [{"line_id": "line-1", "item_id": "product-1", "sku_id": "",
             "quantity": 2, "amount": "20.00"}]
}
```

状态限定为 `paid / unpaid / cancelled / refunded / fulfilled`。退款中也必须返回 `refunded` 或 `refund_pending:true`。行金额是行实付，所有行实付加运费须等于总实付。买家用订单绑定的稳定标识，不用昵称。含定金、拆单、混合履约或特殊退款规则的订单，只有能准确归一化时才开放，不能把未知状态猜成已付款。

### 交付提交

请求字段为 `idempotency_key`、`order_id`、`line_id`、`buyer_id`、`item_id`、`sku_id`、`quantity`、`amount`、`currency`、`payload`。

```json
{"type":"card","cards":["仅示例，不是真实卡密"]}
{"type":"link","content":"该商品的资料地址和说明"}
{"type":"physical","carrier":"快递公司","tracking_number":"运单编号"}
```

服务端必须在交付事务内重新校验付款、退款、商品、数量、金额及收件人，锁定对应订单。相同幂等键和内容返回原回执；改内容或同一业务单换键再发必须拒绝。写入订单系统供正确买家读取后，才能返回 `sent`。单纯“平台已标记发货”不能冒充卡密已经交给买家。

HTTP 错误、超时、不完整回执都会记为待核实，工作台不会自行重发。接口开发者应保留幂等交付记录，供商家按原订单和键核对。

## 当前验证范围

主项目包含库存并发、重复通知、进程中断、退款变化、规则停用、HTTP 签名、工作台三类商品操作和轮询恢复测试。商城接口另有隔离数据库测试。它们证明测试条件下的代码行为，不能代替实际店铺授权后的付款与发货验收。

闲鱼和淘宝的官方“无需物流发货”接口只标记发货，不会替你发送卡密；京东 POP 订单接口不覆盖通用虚拟订单。接入时应使用该店铺与类目获准的接口，详见 [闲鱼服务端文档](https://open.goofish.com/doc/development/dev/server.html)、[淘宝无需物流发货说明](https://developer.alibaba.com/docs/doc.htm?articleId=101128&docType=1&treeId=1)、[京东订单接口目录](https://jos.jd.com/apilistnewdetail?apiGroupId=55&apiId=14263&apiName=null)。
